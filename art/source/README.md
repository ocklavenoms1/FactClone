# art/source — drop your Tripo GLBs here

The handoff point between Tripo and the render pipeline. Nothing here is
generated by the build; everything here is authored by you.

## Naming is the contract

The build looks files up **by name** from [`../assets.json`](../assets.json).

| File | Becomes |
|---|---|
| `smelter.glb` | `smelter_idle.png`, `smelter_smelting.png` |
| `chest.glb` | `chest.png` |
| `power_pole.glb` | `power_pole.png` |

Assets listed in the manifest with no GLB present are reported as skipped, not
as errors — so all twenty rows can exist long before the files do.

## Getting a model out of Tripo

You already have the **Tripo3d Blender Bridge** add-on installed
(`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\Tripo3d_Blender_Bridge`).
It runs a WebSocket server inside Blender on port 60600 and receives models
pushed from Tripo Studio, which spends **Studio subscription credits**. The API
wallet is a separate pool and is currently at zero, so the bridge (or a plain
manual download) is the route to use.

1. Generate in Tripo Studio using the prompt from [`../PROMPTS.md`](../PROMPTS.md).
2. Open Blender — the bridge only listens while Blender is running.
3. Push the model from Tripo Studio; it lands in the open scene.
4. **File → Export → glTF 2.0 (.glb)**, with **Selected Objects** ticked.
5. Save as `art/source/<name>.glb`.

Downloading the GLB from Studio and copying it here is equivalent.

## What the pipeline expects

Scale, position and rotation are all normalized for you, so most things do not
matter. These do:

- **Export `.glb`**, not `.gltf` + loose files — no missing-texture failure mode.
- **Delete strays** — any ground plane, backdrop, camera or light Tripo included.
- **Do not pre-orient or pre-scale.** Turn Tripo's auto-orient and auto-scale
  **off** and let Blender own both. `yaw_correction` in the manifest handles
  facing, and it is read off an 8-way turnaround, never guessed:

  ```bash
  blender -b art/template.blend -P art/blender/turnaround.py -- \
      --glb art/source/<name>.glb --name <name> --footprint 1
  ```

- **Tall thin assets use `"fit": "height"`** in the manifest, not `footprint`.

### Moving parts

Export the body and the moving part as **two files**, with the part's **pivot
at the world origin** — the renderer spins the part about world Z, so the
origin *is* the hinge. In Blender: place the 3D cursor at the pivot,
**Object → Set Origin → Origin to 3D Cursor**, then move the object so its
origin sits at `(0,0,0)`.

Read [`../PIPELINE.md`](../PIPELINE.md) §9 first — for most animated parts the
recommendation is to keep drawing them programmatically and generate nothing.

## Regenerate rather than repair

Wrong proportions, cartoon look, cobbled detail, parts sticking outside the
footprint: **generate it again.** Blender fixes geometry and material range;
only the prompt fixes style, form, and detail density.
