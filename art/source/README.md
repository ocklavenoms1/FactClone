# art/source — drop your Tripo GLBs here

This folder is the handoff point between Tripo and the render pipeline.
Nothing in here is generated by the build; everything here is authored by you.

## Naming is the contract

The build looks up files **by name** from `art/assets.json`. Get the name
right and there is nothing else to configure.

| File | Becomes |
|---|---|
| `chest.glb` | `art/sprites/chest.png` |
| `smelter.glb` | `smelter_idle.png` + `smelter_smelting.png` |
| `power_pole.glb` | `power_pole.png` |
| `inserter_body.glb` + `inserter_arm.glb` | `inserter_f0..f180.png` |

Then run, from the repo root:

```bash
powershell -File art\build_sprites.ps1 -Sheet
```

Assets listed in the manifest with no GLB present are reported as skipped, not
as errors — so you can add all 20 rows to the manifest now and fill the folder
in over time.

## Getting a model out of Tripo — the Studio → Blender bridge

You already have the **Tripo3d Blender Bridge** add-on installed
(`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\Tripo3d_Blender_Bridge`).
It runs a WebSocket server inside Blender on port 60600 and receives models
pushed from Tripo Studio. Use this route: it spends your **Studio subscription
credits**, not API credits (the API wallet is separate and currently at zero).

1. Generate the model in Tripo Studio using the prompt from `art/PROMPTS.md`.
2. Open Blender (the GUI — the bridge only listens while Blender is running).
3. In Tripo Studio, send the model to Blender. It arrives in the open scene.
4. Select the imported object(s) and export:
   **File → Export → glTF 2.0 (.glb)**, with **Selected Objects** ticked.
5. Save as `art/source/<name>.glb` using the exact name from the table above.

Downloading the GLB from Tripo Studio manually and copying it here works
identically — the bridge just saves a couple of steps.

## What the pipeline expects of the mesh

The renderer normalizes scale and position for you, so most things do not
matter. These few do:

- **Upright, +Z up.** The importer honors glTF's Y-up convention; if a model
  arrives lying down, fix its rotation in Blender and re-export.
- **Facing −Y.** For anything with a front (inserters, 4-way buildings), the
  front should point along −Y, which is toward the bottom-front of the rendered
  frame. Rotate before exporting; the `--yaw` values assume this.
- **One object or one hierarchy.** Multiple loose top-level objects are fine —
  they get parented together — but delete stray cameras, lights, and any
  ground plane or backdrop Tripo may include.
- **Textures embedded.** Export as `.glb` (binary), not `.gltf` + separate
  files, so the render step has no missing-texture failure mode.

### Moving parts need one extra rule

For an animated building, export the body and the moving part as **two files**,
and put the part's **pivot at the world origin** before exporting — the
renderer spins the part about world Z, so the origin *is* the hinge. In
Blender: place the 3D cursor at the intended pivot, then
**Object → Set Origin → Origin to 3D Cursor**, then move the object so its
origin sits at `(0,0,0)`.

## Regenerate rather than repair

If a model comes back with the wrong proportions, a cartoon look, or scene
clutter, generate it again with the prompt adjusted. Blender fixes *geometry*
problems; only the prompt fixes *style* problems. See `art/PROMPTS.md`.

## Note on the current contents

Any GLB in here right now is a **crude proxy** built by
`art/blender/make_proxies.py` to validate the pipeline before real assets
existed. They are correct in proportion and nothing else. Overwrite each one as
you generate the real model — no other change is needed.
